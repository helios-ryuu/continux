\begin{abstract}
This study builds and evaluates \textbf{Continux}, a real-time Data Lakehouse architecture for intelligent transportation data on a three-server K3s cluster. The system converts NYC TLC Yellow Taxi records from Parquet to JSONL, replays events with Vector, brokers them through Redpanda, processes streaming SQL in RisingWave, writes Iceberg output to MinIO, manages deployment with Argo CD, and observes behavior through VictoriaMetrics/Grafana dashboards. The artifact is evaluated through one controlled replay and a Blue/Green materialized-view cutover: the public MV moves from \texttt{69/986} to green logic \texttt{69/978}, the query loop records no errors, RisingWave does not restart, and the runbook records a \texttt{0.145226 s} swap duration. The result shows that public query logic can be updated without observed interruption in the measured window, while end-to-end exactly-once behavior and automatic Iceberg sink migration are not claimed.
\end{abstract}

\noindent\textbf{Keywords:} Data Lakehouse, stream processing, Materialized View, Blue/Green cutover, RisingWave, Apache Iceberg, GitOps, K3s, ITS.
